# 설계 결정 · 하지 않은 것 · 남은 것

## 토큰 회계

**`thoughts` 를 `output` 에서 빼지 않습니다.** 실측 항등식이
`input + output + thoughts === total` 이므로 빼면 조각 합이 합계에 못 미칩니다.
`src/shared.js` 의 `decomposeTokens` 에 세 번째 분기를 넣었고, 조건에
`cacheWrite === 0` 을 포함했습니다 — Gemini 로그에는 캐시 쓰기 필드가 없어 항상
0 인데, 이 조건이 없으면 캐시 쓰기가 있는 Claude 기록이 우연히 같은 항등식을
만족할 때 엉뚱한 분해가 먼저 잡힙니다.

**`cache_in_input` 입니다.** `accounting.mjs` 의 예측값 `cache_disjoint` 를
정정했습니다. 근거는 [measurements.md](./measurements.md#계획서-예측과-어긋난-두-가지).

**`tool` 의 자리를 가정하지 않습니다.** 전 코퍼스에서 0 이라 `total` 안인지
밖인지 모릅니다. 값은 로그가 준 대로 `toolTokens` 에 넣고, 0 이 아닌 `tool` 이
나타나 항등식이 깨지면 보정하지 않고 드러냅니다:

- 이벤트 등급이 `local_exact` → `partial` 로 내려갑니다
- `discrepancies` 에 `reportedTotalTokens` / `summedTotalTokens` 가 남습니다
- 수집기 상태의 `identityMismatches` · `toolTokensSeen` 이 올라갑니다
- `decomposeTokens` 는 fallback 으로 떨어져 화면에 "겹침 미확인" 이 붙습니다

**`cached > input` 도 같은 방식입니다.** 값을 잘라내지 않고
`fieldQuality.cachedInputTokens` 만 `partial` 로 내리고 `cacheOutsideInput` 을
셉니다. 잘라내면 원장이 로그와 달라집니다.

## 프로젝트 귀속

우선순위는 셋입니다.

1. 세션 문서의 `directories` 가 **정확히 하나**면 그 경로. 가장 직접적인 근거라
   색인보다 우선합니다. 둘 이상이면 어느 것이 이 세션의 프로젝트인지 로그가
   말해 주지 않으므로 **고르지 않습니다** — 하나를 고르면 남의 경로를 붙입니다.
2. 디렉터리 이름이 `projects.json` 색인에 있으면 그 경로. 이름은 다른 provider 와
   같은 규칙(경로 마지막 조각)으로 만듭니다. 한 슬러그가 두 경로를 가리키면
   모호하므로 그 슬러그를 버립니다.
3. 색인에 없으면:
   - 슬러그형이면 **슬러그가 우리가 아는 전부**입니다. 이름으로 그대로 씁니다.
   - 해시형이면 경로도 이름도 모릅니다. `gemini:<해시 12자>` 를 식별자로 씁니다.

**`unknown-project` 로 합치지 않는 이유**: 해시형 디렉터리 중 chats 를 가진 것이
81개입니다. 하나로 접으면 서로 다른 프로젝트 81개가 프로젝트 목록에서 한 줄이
되고, 토큰이 전부 그 한 줄에 몰립니다. `gemini:` 접두사는 Windows 경로 조각에
쓸 수 없는 문자라 폴더 이름으로 오해되지 않습니다.

색인은 reconcile 마다 다시 읽습니다 — 프로젝트가 추가되면 그때 이름이 풀려야
합니다. 상태에 `projectsIndexed` / `projectsResolved` / `projectsUnresolved` 를
따로 실어, 화면이 "이름을 모르는 프로젝트가 몇 개인지" 말할 수 있게 했습니다.

## 프라이버시

**읽지 않는 것**

```
메시지 content · displayContent · thoughts 본문 · 문서 summary · memoryScratchpad
toolCalls 의 args* · result · resultDisplay · description
<프로젝트 디렉터리>/logs.json   ← 사용자 프롬프트 원문
~/.gemini/oauth_creds.json     ← access token
```

`thoughts` 는 두 포맷에서 모양이 다릅니다(`.json` 은
`{subject, description, timestamp}` 객체 배열 8,452건, `.jsonl` 은 문자열). 어느
쪽도 열지 않고, 쓰는 것은 `tokens.thoughts` 숫자뿐입니다.

**저장하는 것**

- 도구 **이름** (`toolCalls[].name`) — 세션 흐름의 단계 분류 근거입니다
- 경로는 인자의 경로 키에서만 뽑고, **마지막 두 조각만** 남깁니다
  (`src/deep/app.js` → `deep/app.js`). Claude 어댑터와 같은 규칙입니다
- `cwd` — 다른 provider 와 같습니다. `project_aliases` 의 가림·별칭이 그대로 적용됩니다

`test/gemini-collector.test.mjs` 가 센티넬 6종을 픽스처에 심고 SQLite 파일
바이트와 스냅샷 응답 양쪽에서 없는 것을 확인합니다. 픽스처에는 `oauth_creds.json`
도 센티넬과 함께 넣어 두었습니다 — 어댑터가 그 파일을 열면 검사가 잡습니다.

## 하지 않은 것

- 값이 0 인 `tool` 의 `total` 내 위치를 추정하기
- 항등식이 깨진 레코드를 보정해서 맞추기
- 해시 디렉터리를 `unknown-project` 로 합치기
- 컴팩션 경계를 추측으로 만들기 (두 포맷 어디에도 표시가 없습니다)
- hook 을 지원하는 것처럼 표시하기 (`capabilities.hooks = false`)
- 서버 한도가 있는 것처럼 표시하기 (`serverQuota = false`)
- `$set` 을 문서 모델로 재구성하기 — 토큰이 실리지 않으므로 필요가 없습니다

## 이 마일스톤이 드러낸 화면 결함 두 건 (고침)

Gemini 로그는 전부 이번 달보다 이전이었습니다. 그래서 **"지난달까지만 쓴
provider" 라는 상황이 처음 생겼고**, 그때 화면이 데이터를 못 보여준다는 것이
드러났습니다. Codex·Claude 는 둘 다 당월 활동이 있어 가려져 있던 문제입니다.

### D1. "전체" 기간이 실제로는 "이번 달"이었습니다

세 층이 각자 다른 가정을 했습니다.

```
뷰    sinceFor('all') → null            "전체 기간을 뜻한다"
전송  clean() 이 null 파라미터를 제거     (src/usage-client.js)
서버  since 없으면 ?? defaultSince()     "생략했으니 이번 달"
```

서버에는 "생략"과 "전체"가 똑같이 도착했습니다. 고친 방식은 **전체 기간을 명시적
플래그로 만드는 것**입니다 — `since` 생략 시 이번 달로 좁히는 기본값은 클라이언트
실수로 전 구간을 훑지 않게 하는 보호막이라 그대로 두고 싶었습니다.

`service/api-server.mjs` 의 `#since(query)` 하나가 `all` 플래그(`1`/`true`/`yes`)를
보고 판정하며, `since`/`until` 을 받는 5개 라우트가 모두 이 헬퍼를 씁니다.
`all` 이 켜지면 함께 온 `since` 는 무시합니다 — 둘이 오면 더 넓은 쪽이 의도입니다.

### D3. 두 화면이 D1 을 따라오지 못했습니다 (고침)

D1 이 세션 흐름을 전체 기간으로 넓히자 두 곳이 어긋났습니다. 검증 라운드가
둘 다 잡았고, 하나는 **잘못된 쓰기**까지 갈 수 있었습니다.

- **`프로젝트` 화면**: 세션 흐름에서 "프로젝트 →" 로 넘어온 키가 이번 달 목록에
  없으면 `activeKey` 가 아무 안내 없이 **이번 달 1위 프로젝트**로 대체됐습니다.
  그 프로젝트의 이름·토큰·세션이 넘어온 프로젝트인 것처럼 그려지고, 별칭 저장·
  경로 가림 버튼도 그쪽에 걸렸습니다. 실측: 전체 기간 프로젝트 230개 vs 이번 달
  30개, 전체 기간 상위 40 세션 중 8개가 이번 달 목록에 없는 프로젝트였고 Gemini
  세션은 전부 이 경로였습니다. 지금은 넘어온 키를 대체하지 않고, 기간 칩을 두어
  전체 기간으로 넓히며, 못 찾으면 "찾지 못했다"고 적습니다.
- **`AI 사용량` 의 provider별 상세표**: 스냅샷의 이번 달 `totals` 를 읽어서,
  기간을 전체로 넓히면 위쪽 차트·기간 합계는 9.87억을 그리는데 같은 provider 행은
  전부 `—` 이고 배지가 "관측 대기" 였습니다 — 한 화면이 같은 provider 를 두고 두
  가지를 주장했습니다. 지금은 이미 받아온 `timeseries.series` 를 provider 별로
  접어 같은 기간을 봅니다. 배지도 "관측한 적 없음"과 "이 기간 기록 없음"을
  구분합니다.

### D2. provider 필터 칩이 이번 달 기준으로 잠겨 있었습니다

```js
disabled={(provider.totals?.eventCount ?? 0) === 0}        // 이번 달 창
disabled={(provider.allTimeTotals?.eventCount ?? 0) === 0} // 고침
```

`totals` 는 스냅샷의 이번 달 값입니다. 그것으로 잠그면 기간을 "전체"로 바꿔도
칩이 계속 비활성이라, Gemini 의 9.8억 토큰이 DB 에 있고 API 로는 나오는데
**화면의 어느 경로로도 볼 수 없었습니다.** 판정 기준은 "이 provider 가 한 번이라도
관측된 적이 있나" 여야 합니다.

`AI 사용량` 화면은 기간 선택지가 30일까지여서 칩을 열어도 닿지 않았습니다.
`전체` 를 추가했습니다 — 시계열 버킷은 활동 구간에만 생기므로 전체 기간이라도
948개로 부담이 없습니다([measurements.md](./measurements.md#시계열-비용)).

계약은 `test/period-all-time.test.mjs` 가 서버와 전송 양쪽에서 못박습니다. 한 층만
고치면 다시 어긋나기 때문입니다.

## 세션 정체 — 로그의 sessionId 를 쓰지 않습니다 (v2)

처음에는 로그의 `sessionId` 를 세션 정체로 썼습니다. 검증 라운드에서 그것이
성립하지 않는다는 것이 드러났습니다.

```
고유 sessionId 377개 / 세션 파일 807개
그중 67개가 여러 파일에 걸쳐 있고, 하나('a2a-server' — UUID 도 아닙니다)는
파일 347개가 공유합니다.
```

`turns` 의 키가 `(provider, session_id, turn_index)` 이므로 세션이 유일하지
않으면 파일들이 턴 1,2,3… 을 서로 덮어쓰고, `resetTurns` 는 형제 파일의 턴
원장까지 지웁니다. 실제로 그랬습니다 — 턴 행이 2,520 으로 줄어 있었고 최대 턴
번호가 63 에서 멈춰 있었습니다.

Gemini 의 실제 대화 단위는 **파일 하나**입니다. 그래서 v2 는 경로에서 정체를
만듭니다(`detector.mjs` 의 `geminiSessionKey` — 상대 경로의 sha1 앞 16자).
경로를 그대로 쓰지 않고 해시하는 이유는 세션 id 가 URL 에 실리기 때문입니다.

결과: 세션 807개(파일과 1:1), 턴 2,887개 — 실측한 실제 사용자 프롬프트 수
2,887 과 정확히 같습니다. **토큰 합계는 변하지 않았습니다**(987,623,731) —
중복 제거가 `message.id` 기반이라 세션 정체와 무관합니다.

이미 쌓인 원장은 재해석만으로 고쳐지지 않습니다: `upsertUsageEvent` 는
`event_key` 로 찾아 갱신하면서 `session_id` 는 건드리지 않습니다. 그래서
수집기가 옛 정체로 묶인 세션을 발견하면 이 provider 의 원장을 한 번 비우고 다시
만듭니다(`#resetLegacyIdentity`, 상태의 `identityResets`). 전부 로컬 로그에서
파생되는 값이라 잃는 것이 없습니다.

## $set 은 턴 경계가 아닙니다 (v2)

처음에는 `$set.messages` 의 사람 메시지를 턴 경계로 받았습니다. 근거는 "일반
줄에 한 번도 안 나온 id 가 하나 있다" 였는데, 그 하나를 얻는 대가가 너무
컸습니다.

```
$set.messages 안 사람 메시지 1,982건 → 고유 id 단 1개
파서가 만든 턴 경계 4,869 vs 실제 고유 프롬프트 2,802   (1.7배)
```

같은 프롬프트를 1,982번 다시 적은 것이고, 그때마다 턴 번호가 올라갔습니다.
토큰은 애초에 `$set` 에 실리지 않으므로(3,063줄 중 0건) 건너뛰어도 사용량은
하나도 잃지 않습니다. 지금은 `$set` 이 어떤 형태든 이벤트를 만들지 않습니다.

## 남은 것

- **증분 tail 경로에 테스트가 없습니다.** `.jsonl` 을 중간부터 이어 읽을 때 턴
  번호 승계와 세션 정체가 맞는지는 코드 대조로만 확인했습니다.
- **`projectsResolved` / `projectsUnresolved` 는 프로젝트 수가 아니라 스캔한
  파일 수의 누적입니다.** 이름이 오해를 부르고, 이 값을 표시하는 화면도 없습니다.
- **OTLP 같은 보강 레인은 없습니다.** Gemini 는 JSONL/JSON 로컬 로그가 전부이고,
  다른 기기·웹 앱에서의 활동은 여전히 증명할 수 없습니다.
- **`tool` 토큰의 자리**는 0 이 아닌 값이 나타나는 날 확정됩니다. 그때 항등식이
  깨진 채로 카운터가 올라갈 것이므로, 그 신호를 보고 다시 재면 됩니다.
