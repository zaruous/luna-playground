# Gemini 적용 가능성 표 (M5 사후 점검)

[LLM별 기능지원표.md](../LLM별%20기능지원표.md)는 Claude/Codex/Gemini/Cursor 4종을
나란히 놓고 **능력 단위로** 무엇이 되는지 봅니다. 이 문서는 같은 질문을 한 칸 더
내려가서 봅니다 — **화면 요소 하나하나가 Gemini 데이터로 실제로 옳게 그려지는가.**
능력이 O 여도 그 능력을 읽는 화면이 다른 provider 회계를 전제하고 있으면 숫자가
조용히 어긋나기 때문입니다(아래 세션 흐름의 턴 토큰이 정확히 그 경우입니다).

**행 기준: 실제 화면 코드를 먼저 읽었습니다.** `src/views/` 의 14개 파일
(`DashboardView` · `UsageView` · `ProjectView` · `SessionView` · `SessionTurns` ·
`TurnDetail` · `DetailView` · `ToolContentModal` · `BudgetView` · `QuotaHistory` ·
`AlertView` · `SettingsView` · `Bits` · `Chart` · `PieChart`)을 전부 읽고 그 안의
JSX 섹션·카드·칩·패널을 하나씩 행으로 옮겼습니다. 판단 근거는
[measurements.md](./measurements.md) · [decisions.md](./decisions.md) ·
[formats.md](./formats.md) · [antigravity.md](./antigravity.md) 의 기존 실측과
`service/providers/gemini/*` 의 코드입니다.

**여기에만 새로 잰 것이 하나 있습니다.** 회계 항등식과 화면 표시가 실제로 맞는지
확인하려고 이 머신의 살아 있는 원장(`%APPDATA%/nyang-token-tracker/usage.sqlite3`,
2026-08-25)을 읽기 전용 사본으로 떠서 다시 셌습니다. 그 값은
[measurements.md](./measurements.md) 의 2026-08-21 코퍼스(807 파일 · 12,319 이벤트 ·
987,623,731 토큰)와 **다릅니다** — [antigravity.md](./antigravity.md) 가 적어 둔 대로
사용자가 `~/.gemini` 를 지운 뒤라 코퍼스가 훨씬 작습니다.

```
Gemini 현재 원장 (2026-08-25)
  이벤트 112 · 4,687,248 토큰 · 세션 5 · 프로젝트 4 · 모델 1
  reasoning 73,761 · cacheWrite 0 · tool 0 · 전부 measurement_quality = local_exact
  턴 경계 30 · 턴이 붙은 이벤트 112/112 (100%) · turn_index 0 버킷 0건 · compacted 0/30
  활동 구간 2026-03-11 ~ 2026-04-02 (이번 달 이벤트 0건)
  원본 5개 전부 `.json` 스냅샷 · provider_scan_state 7행 전부 content_hash 보유 · parser_version 2
  ~/.gemini/tmp 디렉터리 9개 전부 슬러그형(해시형 0) · projects.json 항목 7개 · antigravity-cli 없음
```

즉 지금 이 머신에서 살아 있는 상태는 `legacy-observed` 하나이고, `gemini:<해시>`
폴백과 `agy-unmeasured` 는 **코드 경로로는 실재하지만 지금 재현되지 않습니다.**
아래 표에서 그 둘은 "코드로 확인, 현재 원장에서는 미재현"으로 구분해 적습니다.

## 표기 범례

| 표기 | 뜻 |
|---|---|
| **O** | 화면 요소가 Gemini 데이터로 의도대로 동작함 — 코드와 실측으로 확인됨 |
| **△** | 그려지긴 하지만 일부가 비거나 뜻이 달라짐 — 값이 항상 0, 근거가 없어 생략, 다른 provider 와 같은 칸인데 같은 뜻이 아님 |
| **X** | Gemini 에 해당 신호가 없거나 어댑터가 아직 없음 — 화면이 그 사실을 표기함 |

⑩ **(코드 결함) 턴 토큰 식이 Gemini 회계를 안 봅니다 — 이 점검에서 새로 잰 것.**
`store.mjs:1467-1472` 의 턴 토큰 = `promptSideTokens + outputTokens` 이고
[session.md](../menus/session.md):199 의 정의도 같습니다. Claude·Codex 는
`output ⊇ reasoning` 이라 이 식이 완전한데, **Gemini 는 thoughts 가 output 밖에
있어서**([measurements.md](./measurements.md#1-thoughts-가-output-밖에-있습니다))
턴 토큰이 항상 thoughts 만큼 적습니다. 현재 원장 실측:

```
Gemini  Σ(input + cacheWrite + output) = 4,613,487
        Σ total_tokens (원장)          = 4,687,248
        차이                           =    73,761  = Σ reasoning 전액 (-1.57%)
Claude  같은 식                        = 4,570,807,564 = 원장과 정확히 일치
```

reasoning > 0 인 이벤트가 112건 중 91건(81.3%)이고, 얼어 있던 코퍼스에서도 `.json`
레코드의 72.48% 가 thoughts 를 갖고 있었습니다. 영향 범위는 세션 흐름의 **비싼 턴 표
토큰 열 · "가장 비싼 턴" 카드 · 단계별 배분 · 프로젝트 화면의 펼친 비싼 턴** 넷이고,
같은 화면의 세션 총 토큰은 원장 `total_tokens` 를 쓰므로 맞습니다 — **한 화면 안에서
턴 합과 세션 합이 어긋납니다.** `decomposeTokens`(`shared.js:635-648`)는 이 예외를 이미
처리하고 있으므로, 고칠 곳은 회계별 분기가 없는 이 한 식입니다.

⑪ **[antigravity.md](./antigravity.md):76-82 의 화면 정책 표와 코드의 조건이 다릅니다.**
표는 `agy-unmeasured` 를 "**agy 있음, legacy 없음** + 원장 0" 으로 정의하는데,
`geminiSourceState` 의 마지막 분기(`shared.js:465-471`)는 `agyPresent && !hasLedger`
만 봐서 **legacy chats 유무를 확인하지 않습니다.** 그래서 chats 와 agy 가 둘 다 있고
첫 스캔이 아직 안 끝난 동안 화면이 `agy 사용 중 · 토큰 회계 미확립` 이라고 적습니다 —
실제로는 측정 가능한 chats 를 읽고 있는 중입니다. `geminiTokensBlocked` 가 `pending`
보다 먼저 걸리므로(`DashboardView.jsx:418-424`) 숫자 자리에 `로딩중..` 대신 `—` 가
나오고, AI 사용량·세션 흐름의 provider 칩도 "토큰 회계 미확립" 이유로 잠깁니다. 좁은
창이지만, chats 에 토큰 있는 메시지가 하나도 없는 계정에서는 영구히 이 상태입니다.
