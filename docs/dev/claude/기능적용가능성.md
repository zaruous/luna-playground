# Claude 적용 가능성 표

[LLM별 기능지원표.md](../LLM별%20기능지원표.md)는 Claude/Codex/Gemini/Cursor 4종을
나란히 놓고 **기능 단위로** 무엇이 지원되는지 봅니다. Claude 열은 거의 전부 O 인데,
그 O 가 "화면의 그 칸이 실제로 맞는 값을 보여준다"는 뜻인지는 기능 이름 한 줄로는
안 갈립니다. 이 문서는 그 질문 하나만 봅니다 — **화면/기능 단위로, Claude 가 그
칸의 전제를 실제로 충족하는가.**

Cursor 판([cursor/기능적용가능성.md](../cursor/기능적용가능성.md))은 "어댑터가 없는
provider 를 붙일 수 있는가"를 앞을 보고 물었습니다. Claude 는 어댑터가 이미 있으니
질문의 방향이 반대입니다: **화면이 전제하는 것과 실제 데이터가 보장하는 것이
어긋나는 자리를 찾는 것**입니다. 그래서 △ 는 "아마 되는데 미확인"이 아니라
**"동작하지만 알려진 결손이 있음"**, X 는 "신호가 없음"이 아니라 **"이 화면 요소는
Claude 에 적용되지 않거나 아직 만들어지지 않았음"** 입니다.

**행 기준: 실제 화면 코드를 먼저 읽었습니다.** `src/views/` 의 `DashboardView.jsx`
· `UsageView.jsx` · `ProjectView.jsx` · `SessionView.jsx` · `SessionTurns.jsx` ·
`TurnDetail.jsx` · `DetailView.jsx` · `ToolContentModal.jsx` · `BudgetView.jsx` ·
`QuotaHistory.jsx` · `AlertView.jsx` · `SettingsView.jsx` · `Bits.jsx` ·
`Chart.jsx` · `PieChart.jsx` 를 전부 읽고, 그 안의 JSX 섹션 하나하나를 행으로
옮겼습니다. 근거는 Claude 어댑터 코드(`service/providers/claude/*.mjs`,
`accounting.mjs`, `tool-phases.mjs`)와 기존 실측
([claude-code-adapter.md](../../claude-code-adapter.md),
[menus/*.md](../menus/), [LLM별 기능지원표 상세.md](../LLM별%20기능지원표%20상세.md))
이고, 새로 측정한 데이터는 없습니다.

## 표기 범례

| 표기 | 뜻 |
|---|---|
| **O** | 설계대로 동작함 — 화면이 전제하는 신호가 Claude 데이터에 있고, 코드가 그것을 그대로 씁니다 |
| **△** | 동작하지만 알려진 결손이 있음 — 버전 게이트·부분 커버리지·화면 하나가 여러 지표를 묶는데 그중 일부만 됨. **결손의 근거를 반드시 인용합니다** |
| **X** | Claude 에 적용되지 않음 — 신호 자체가 없거나(서버 한도), Claude 에는 필요 없거나(자격증명), 화면이 아직 만들어지지 않음 |
